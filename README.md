# Oman 13C-SIP Repository

Code and data-processing workflow investigating carbon assimilation rates and preferences of the serpentinite-hosted subsurface microbiome in the Samail Ophiolite (Oman), using single-cell stable isotope probing (nanoSIMS-SIP) and cavity ring-down spectroscopy (CRDS-SIP).

## Code Availability

All analysis code is available at [github.com/tacaro/Oman-2023](https://github.com/tacaro/Oman-2023). All data generated during this study are available on the Open Science Framework: [osf.io/7e6ua](https://osf.io/7e6ua/).

This repository contains every script used to produce the results and figures in the manuscript. Scripts that were exploratory, superseded, or out of scope for this manuscript have been moved to [`archive/`](archive/) rather than deleted, so that the active workflow (below) is unambiguous; see [`archive/README.md`](archive/README.md) for what's there and why.

## Requirements

- **R** 4.3.2 was used to produce the manuscript's original results. 
- **Quarto** (`.qmd` files) and R Markdown (`.rmd`/`.Rmd` files, rendered via `knitr`).
- **Python 3** (only for `00_gc_data_extraction_script.py` and the Python chunks in `26_nanoSIMS_viz.qmd`), with `numpy`, `pandas`, `matplotlib`, `opencv-python` (`cv2`), `matplotlib_scalebar`, and the [`sims`](https://github.com/zanpeeters/sims) package for reading Cameca nanoSIMS `.im` files. `renv` manages R packages only — Python dependencies are not pinned by a lockfile.
- Key R packages: `tidyverse`, `readxl`/`writexl`, `cowplot`, `gt`, `janitor`, `ggdist`, `ggsci`, `latex2exp`, `ineq`/`gglorenz` (Gini coefficient), `phyloseq`/`dada2`/`decontam`/`microViz`/`microbiome` (16S rRNA), `isoCRDS` ([github.com/KopfLab/isoCRDS](https://github.com/KopfLab/isoCRDS), CRDS data), the [IsoVerse](https://www.isoverse.org/) suite (`isoreader`/`isoprocessor`/`isotopia`/`isoprocessCUBES`, DIC/IRMS data reduction), `chemCal`, `DescTools`, `marelac`, `plater`, `stargazer`, `tidymodels`, and others — the full, exact set (391 packages including transitive dependencies) is pinned in [`renv.lock`](renv.lock).

No script writes outside `data_output/`, `fig_output/`, or `cache/`, so scripts can be re-run without risk to raw data in `data/`.

### Reproducing the R environment

This repository uses [`renv`](https://rstudio.github.io/renv/) to pin exact package versions. To reproduce the environment:

```r
install.packages("renv")   # if not already installed
renv::restore()            # installs every package at the version recorded in renv.lock
```

Run this from the repository root (with `om23.Rproj` open, or after `setwd()` to the repo root) — `renv::restore()` reads `renv.lock` and installs into an isolated, project-local library at `renv/library/`, without touching your regular R package library. `chemCal`, `DescTools`, `marelac`, `plater`, `stargazer`, `ineq`, and `gglorenz` come from CRAN; `phyloseq`, `dada2`, `decontam`, and `microbiome` come from Bioconductor; `isoCRDS`, `isoreader`, `isoprocessor`, `isotopia`, and `isoprocessCUBES` are installed from GitHub (`KopfLab/isoCRDS`, `isoverse/isoreader`, `isoverse/isoprocessor`, `isoverse/isotopia`, `CUBESSIL/isoprocessCUBES`) — `renv::restore()` resolves all of these automatically from the source recorded in the lockfile.


## Directory structure

- `data/` — raw data reported in this study (see [`data/README.md`](data/README.md) for contents). Some large/high-file-count raw subfolders are excluded from git via `.gitignore`; the complete raw dataset is on OSF.
- `source/` — shared helper functions and ggplot2 theme/palettes, `source()`'d by many scripts (see [`source/README.md`](source/README.md)).
- `cache/` — intermediate `.RDS`/`.rds` files that let downstream scripts skip expensive re-computation (e.g. `cache/SIMS_assim_data.RDS`, the processed nanoSIMS-SIP dataset used by 7 different downstream scripts). Regenerated by re-running the upstream script.
- `data_output/` — tidy, processed datasets (`.xlsx`, `.html` tables) written by analysis scripts, consumed by other analysis scripts and/or reported directly in the manuscript's tables.
- `fig_output/` — figures (`.pdf`/`.png`) written by analysis scripts. Populated by running the scripts below, not pre-populated in git.
- `archive/` — scripts and data superseded, exploratory, or out of scope for this manuscript. Kept for future reference.
- `renv.lock`, `renv/`, `.Rprofile`, `.renvignore` — the [`renv`](https://rstudio.github.io/renv/) reproducible-environment setup (see "Reproducing the R environment" above). `renv/library/` (the actual installed packages) is git-ignored, as is standard for `renv` projects — only the lockfile and activation scripts are version-controlled.
- Numbered `.qmd` files at the repository root — the active analysis pipeline, described below.

## Workflow overview

Scripts are numbered in roughly the order data flows through them, but there is no single top-to-bottom execution order — the numbering reflects **independent measurement pipelines** (GC, DIC, IC/ICP, nanoSIMS, 16S, Picarro/CRDS, etc.) that each go from raw instrument data to a processed dataset in `data_output/` or `cache/`, plus a small number of **integration scripts** that read several of those processed datasets to produce the manuscript's main figures. Each script can be run independently as long as its documented inputs already exist (either raw data in `data/`, or a `data_output/`/`cache/` file produced by an upstream script — see "Feeds into" below).

### Suggested execution order

Because each per-measurement script (§1) is independent, they can be run in any order or in parallel. The dependency-sensitive steps are:

1. Run all of §1 (per-measurement processing) — or just the subset needed for a downstream script you care about.
2. Run `03b_nanoSIMS_reanalysis.qmd` (requires `data/Caro DIC Run1 March 6 2/om23_dic_run1.RDS` from step 1). This produces `cache/SIMS_assim_data.RDS`, required by `20_SIP_dynamic_range.qmd`, `13_bootstrapping.qmd`, `07_Cell_Counting_initial.qmd`, `14_power_calcs.qmd`, `15_gini_coef.qmd`, `18_assim_vs_dissim.qmd`, and `22_cell_mass.qmd`.
3. Run `10_16S_Analysis.qmd` and `10b_16S_Analysis_secondset.qmd` (requires DADA2 output from `09`/`09b`), then `10c_combine_16S.qmd`.
4. Run the remaining §2/§3 scripts, which read the `cache/`/`data_output/` files produced above.
5. `14b_input_dist.qmd` and `14c_sensitivity.qmd` both require `14_power_calcs.qmd` to have been run first (they read `cache/mc_input_params.RDS` and `cache/mc_results.RDS`, which it writes).
